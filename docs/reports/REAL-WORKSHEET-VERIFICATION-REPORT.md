# Real worksheet verification pass – report

## 1. What real input was used

- **public/test-worksheet-calibrated.png** – 1920×1080 PNG generated by `scripts/generate-test-image.js`. It has: white background; four black square markers at 5% and 95% (corners); ten gray-outline boxes in a 2×5 grid (no digits or QR inside). This is the only worksheet-like image in the repo and the one the E2E test was written for.

**Not present:** No image in the project contains a QR code or handwritten digits. For full flow verification (QR decode + correctness against real answers) you would need a sample that has: (1) the same four corner markers, (2) a QR code encoding a payload (e.g. with answer_key, template_id, sheet_instance_id), (3) handwritten digits in the ten boxes. Place that file in `public/` (e.g. `public/test-worksheet-with-qr-and-digits.png`) and point the E2E test or manual test at it.

---

## 2. What parts of the flow were truly verified

- **Code path with calibrated image:** The flow was traced for “upload this file”: load image → canvas → `decodeQrFromCanvas` (returns null, no QR) → fetch default layout → `processWorksheet` (detectCornerMarkers expects four markers at ~5%/95%; the calibrated image has them) → warp → crop → OCR → result with digits/confidences; layout has `answer_key` so `correct` is set; App shows Results and Export JSON/CSV. So for this image, the pipeline and UI path are consistent.
- **E2E test path:** `test-upload-real.spec.js` was using a **machine-specific absolute path** (`/Users/openclaw/...`) for the calibrated image, so it could not run on other machines. The test was updated to use a path resolved from the project root (`public/test-worksheet-calibrated.png`). No E2E run was executed in this pass (dev server port/HTTPS vs Playwright baseURL remain unresolved), so “truly verified” here means: the sample file exists, the path is portable, and the code path is consistent with the image content.

---

## 3. What failed or looked fragile

- **E2E test not portable:** The real-worksheet test hardcoded an absolute path from another machine, so it failed on this workspace and would fail for any other developer. This was the single highest-value issue.
- **Port/HTTPS mismatch:** Playwright config uses `http://localhost:5174`; Vite dev server uses port 5175 and HTTPS. So the E2E test cannot hit the running app without changing config or server. Not fixed in this pass (minimal scope).
- **No QR in sample:** The calibrated image has no QR, so QR decode and template_id/sheet_instance_id in the flow were not exercised with real input.
- **Empty digit boxes:** The calibrated image has empty boxes, so OCR sees noise/blank; predictions are arbitrary and correctness is random. Acceptable for “pipeline runs” but not for validating digit accuracy.

---

## 4. Single issue fixed

- **Portable path in real-worksheet E2E test:** In `test-upload-real.spec.js`, the path to the calibrated worksheet was replaced with a resolution from the project root: `path.resolve(__dirname, 'public/test-worksheet-calibrated.png')` using `import.meta.url` and `fileURLToPath` so `__dirname` is the spec’s directory. The test now uses `CALIBRATED_IMAGE` for `setInputFiles`. The same test can be run on any machine that has the repo and the file at `public/test-worksheet-calibrated.png`.
